# Pilot 独立人工复核包

当前状态：**pending，尚无人工审阅结果**。绑定数据版本见 [manifest.json](manifest.json)。本文件是待办说明，不是审批或审阅已完成的证明。

## 先做小批次，记录真实耗时

先盲评打乱后的前 50 个 query-document 组合，并核对 10 个问题及相关证据。逐条记录 `duration_ms`（包括阅读时间），避免把打开文件后的等待时间算入。以实际耗时、争议率决定全量标注资源；不要将草稿生成速度当成人工标注速度。

`document-judgments.jsonl` 共 3,248 项：56 个知识库相关问题 × 58 篇全文。队列隐藏了系统、排名、分数和拟议 grade。文档在 [corpus](../../data/v2/pilot/corpus)。4 个 no-retrieval 任务仍需审阅问题/rubric，但不做文档相关性判断。

## 文档分级

| grade | 判断标准 |
| --- | --- |
| 0 | 不支持所问内容；仅关键词相似、旧版本不适用或错误实体也可为 0，写明原因 |
| 1 | 相关背景，但不直接支持所需事实/方面 |
| 2 | 直接支持至少一个必需事实/方面，但不足以支持完整核心需求 |
| 3 | 对核心需求提供充分、直接的证据 |

填写整数 `grade`、真实 `reviewer` ID 和 `rationale`。空值保持未判断，禁止自动填 0。先看 query 与正文，再判断，避免先看 `review.md` 或拟议 qrels。对 exact 任务按 pattern 的匹配范围、regex/literal、大小写判断；对 read 任务检查选择的文件及内容。缺证据问题仍可能有背景相关文档，不能预设所有文档都为 0。

## 证据与问题

- `evidence-review.jsonl`：48 个 span。检查 source/revision/quote、范围是否完整保留限定条件、是否过宽，以及该证据实际支持哪个事实。
- `case-review.jsonl`：60 个问题。检查自然性、答案是否可得、rubric 的必需限定、替代证据 OR 与组合 AND、family 归组、expected behavior。
- `decision` 取 `accept` / `revise` / `reject`；填写 reviewer、理由和具体建议。发现别的正确证据必须登记，不能只核对现有正例。
- 六个 service-policy 多跳实例是同一合成模板；检查是否可以不经过桥接就找到答案。合成样例只能作为机制诊断。
- 检查 evidence gap 是否确实缺证据、部分可答或需澄清；“本次没检索到”不能证明语料无答案。

## 第二审阅与仲裁

第一轮完成后，第二位审阅者使用新的独立文件，不复制第一人的 grade。至少随机双标 20% 文档判断，所有分歧、负例、多跳关键证据及证据/rubric 进行复核。测试集日后需遵循方案的独立复核要求。

保留两位原始判断、等级混淆矩阵、原始一致率、ordinal weighted κ 与仲裁结论。κ 检查点 0.7 只用于发现指南问题，不足时修订指南并复标，不通过删难题提高一致率。第二个 LLM 调用不等于第二位人工审阅者。

所有实际 top-10 返回结果必须有判断；判断 coverage 和 pool 外新增正例率随结果报告。当前全库队列可避免小语料下只看某一种检索器候选的偏差。
