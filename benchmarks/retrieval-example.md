# Example retrieval measurement

This run used real `qwen3-embedding:0.6b` embeddings from local Ollama and the
pinned MiniLM cross-encoder on CPU, with SQLite and Qdrant Local exact search.
All four configurations used the same published chunks and six authored queries
in `retrieval-cases.jsonl`. This is a regression example: labels are incomplete
and have not been independently judged. It does not establish a general winner.

The snapshot contains 40 documents and 160 chunks. Hybrid retrieves
20 candidates per source; reranking scores the top 20 fused candidates.

| Configuration | Recall@5 | MRR (depth 5) | nDCG@5 | Mean latency (ms) |
| --- | ---: | ---: | ---: | ---: |
| semantic | 1.000 | 1.000 | 0.949 | 74.1 |
| bm25 | 0.917 | 1.000 | 0.983 | 1.4 |
| hybrid | 0.917 | 1.000 | 0.938 | 74.8 |
| hybrid_reranked | 0.917 | 1.000 | 0.986 | 135.9 |

Latency includes query embedding, retrieval, and optional reranking, but excludes
index construction, tokenizer/model loading, and BM25 postings construction.
Mode order rotates across cases. Measurements are one pass on this machine,
without a statistical uncertainty estimate. Local Mode does not measure
Qdrant Server or ANN performance.

Hybrid did not improve recall here. Reranking improved hybrid's graded ordering
without recovering the relevant evidence excluded from its final top five.
All configurations achieved MRR=1 on this small dataset, so these questions
cannot distinguish their first relevant document performance.

The separate frozen-candidate ablation averaged 63.7 ms for
reranking alone. It retains the input pool, original ranks, output ranks and
before/after metrics, so its effect can be inspected separately from retrieval.

[Machine-readable summary](retrieval-example-summary.json) records configuration,
model revisions, package versions, snapshot identity, source hashes and per-case
rank changes. The full report is generated by the command below and retains all
raw candidate text and provenance. [Benchmark instructions](retrieval.md) also
describe the runner for an existing production snapshot.

```sh
uv run --locked --extra rerank python -B benchmarks/run_local_retrieval.py \
  --output /tmp/arkb-new-comparison --offline
```

Omit `--offline` on the first run if the model/tokenizers have not been cached.
The output directory must be new; this command builds an isolated index and
never updates the default application snapshot.
